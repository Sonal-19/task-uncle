# Task Uncle

Bun workspaces monorepo: `apps/api` (Elysia + Drizzle + Postgres) and `apps/web` (Vite + React 19 + TanStack Router/Query + Tailwind v4).
Architecture mirrors `~/Developer/Projects/finance-tracker`.

- Ports: web **3500**, API **4500** in dev (Vite proxies `/api`), **4600** in production (nginx `/api/` → 4600, `conf/task-uncle.conf`). khata-connect uses 3400. DB: `task_uncle` on local Postgres (`apps/api/.env`, see `.env.example`).
- Commands: `bun run dev` (both apps), `bun run typecheck`, `bun run check` (biome), `bun run db:push`, `bun run db:seed` (`-- --reset` replaces data with the demo), `bun run icons` (re-renders PNG icons from `apps/web/public/logo.svg`), `bun run deploy[:backend|:frontend]`.
- Domain: **Event** (project/area) → **Category** (group; `kind: team` when it has `memberIds`, derived, never stored) → **Task**. People are assignees (no accounts). Everything is manual CRUD; the only automation is reminders.
- Shared code: `apps/api/src/lib/shared/types.ts` (domain types, enum value lists, `DataState`, `DEFAULT_SETTINGS`, `statusPatch`, `kindOf`, `newId`) is pure TS imported by both apps (`$/lib/shared/types`; web's `lib/types.ts` re-exports it). The DB enums are built from those lists. The web gets API types through Eden (`@api` → `Server`).
- Ids are UUIDs made by the **client** (`newId()`), so rows created offline keep their id. Creates are idempotent: `POST` with an existing id returns the saved row (`onConflictDoNothing` + select). Deletes are idempotent (200 even if gone).
- API: every response is `ok()` / `fail()`; the web unwraps with `call()` / `callMsg()` (`lib/api.ts`). Logged-in routes use `protectedUser` and are grouped in `controllers/index.ts`. Every query filters by the session `user.id`; ids from a body (eventId, categoryId, memberIds, assigneeId, log taskId) are checked with `lib/services/ownership.ts`. Serializers in `lib/services/serialize.ts` turn rows into the exact shared shapes (ISO strings).
- Auth: opaque token in an httpOnly `token` cookie (`core-auth-service.ts`, same as finance-tracker). Login, logout, `/auth/me`, password reset by emailed OTP (dev: `123456` accepted, code logged). No sign-up: `db:seed` creates `admin@taskuncle.app` / `uncle@123` (the login card shows these in dev builds only). The web keeps a cached copy of the user (`stores/auth-store.ts`, `tu-user`) so it opens offline; `useSession` (in `_app.tsx`) re-checks `/auth/me`, and any 401 logs out.
- Status: `pending | in_progress | done` + timestamps (`startedAt`, `completedAt`). Status changes always go through `statusPatch(row, status, at)` — the API with the edit's `editedAt` (capped at now), the web's optimistic copy with the op's `at` — so both agree. No boolean columns: on/off settings are `"on" | "off"`.
- Offline & sync (`apps/web/src/lib/offline/`), local-first like finance-tracker: the TanStack Query cache is persisted to IndexedDB (`idb.ts`, `PersistQueryClientProvider`, busted per build via `__APP_VERSION__`). **Every** write goes through `queue()` in `sync.ts`: the op is applied to the cache at once by the pure reducer `applyOp` (`apply.ts`, mirrors the API: cascades, kind, statusPatch), stored in the outbox (`outbox.ts`, zustand → IndexedDB) and sent in order by `flush()` (network/5xx → retry with backoff, 409 → "Kept a newer change… Use mine", other 4xx → parked as failed in the sync panel with retry/discard, 401 → logged out, ops kept). Ops must stay deterministic and idempotent (send whole values, e.g. the full `subtasks` list, never toggles) because pending ops are replayed over every fresh server response. Edits to an unsent create fold into it; deleting an unsent row just drops its ops. Edits carry `baseUpdatedAt` (server `updatedAt`; optimistic rows keep it) + `editedAt` (`lib/utils/sync.ts` `editVerdict`). Logout wipes IndexedDB (`forgetDevice`); a different user's data is dropped (`claimDevice`). Import/reset-demo need a connection and drop pending ops.
- Hooks: components never call the API or the outbox directly — they use `hooks/use-data.ts` (query keys in `lib/query-keys.ts`, all start with `"tu"`; GETs in `lib/fetchers.ts`). Pages must prefer cached `data` over `error`.
- Amounts are integers in paise; display only via `formatAmount` / `formatAmountShort` (`lib/format.ts`), forms use `toAmount` / `fromAmount`.
- Dates are `yyyy-MM-dd` strings, task time is `dueTime` `"HH:mm"`; use `DateInput` (dd/MM/yyyy, custom calendar) and `TimeInput` (hour/minute grid + AM/PM), never `<input type="date|time">`.
- Every dropdown is `SelectField` (`components/common/select-field.tsx`, over `ui/select`): pass `options` `{value,label}[]`, `""` is allowed. Never a native `<select>`. Pickers inside phone drawers must not rely on scrolling (the drawer's scroll lock blocks portalled popovers).
- Reminders: pure logic in `lib/reminders/reminder-engine.ts` (`dueReminders`, `nextReminderAt`, quiet hours, overdue boost = half interval); `hooks/use-reminders.ts` (mounted in `AppShell`) runs in **one tab** (Web Lock `tu-reminders`), checks every 60 s + on tab focus from the cached tasks/settings, queues `task.reminded` (`POST /tasks/reminded`, does not bump `updatedAt`) and `log.add`, sends ≤3 task notifications + 1 summary. Notifications go through the service worker (`src/sw.ts`, vite-plugin-pwa `injectManifest`) so they carry **Mark done / Snooze 1h** actions; the SW posts `{type:"task-action"}` to an open tab or opens `/tasks?task=<id>&action=…`. Reminders only fire while the app is open; phase 2: Web Push (VAPID) + server scheduler.
- PWA: hand-written `apps/web/public/manifest.webmanifest` (app shortcuts `?new=task|event`, handled by `useLaunchAction` in `app-shell.tsx`); the custom SW precaches the whole app shell and waits for `SKIP_WAITING` (`registerType: "prompt"`), registered in `lib/pwa.ts` ("A new version is ready" toast, applied by itself when hidden and synced; keeps `beforeinstallprompt` for the one-click Install button / iOS steps in `install-app.tsx`). `InstallCard` sits on top of the dashboard; "Not now" hides it until the next login (`offerInstallAgain()` in `useLogin`). Fonts are bundled (`@fontsource-variable/plus-jakarta-sans`) so the app looks right offline.
- Keyboard shortcuts: actions and keys in `lib/shortcuts.ts` (`n` add task, `shift+n` event, `shift+p` person, `g d/t/e/c/p/n/s` go to, `/` search, `shift+r` sync, `?` cheat sheet, `mod+enter` save the open form). Listener `useGlobalShortcuts` (`hooks/use-shortcuts.ts`), handlers in `app-shell.tsx`; plain keys are ignored while typing or with a sheet open. ⌘K search stays in `command-search.tsx`. A new action needs an entry in `SHORTCUT_ACTIONS` and a handler.
- Phones (<768px): bottom tab bar + FAB, sheets are vaul drawers (`ResponsiveSheet`), swipe a task row right = done, left = snooze 1h, the header shows only the logo + user name (no page title, no greeting, no account menu; Settings / Log out are under the More tab). Desktop: account menu (avatar) in the header, sidebar (Install + sync status above the account) + dialogs.
- Open sheets from anywhere with `useSheets()` (`stores/sheet-store.ts`); the FAB and the `n` shortcut pre-select the event/category of the current route.
